# WorkBuddy 保活集合平台

**Python脚本控制台**用于填写、保存和查看你提供的 Python 保活脚本参数，为不同沙盒分别启动/停止真实 Python 进程并查看日志。首页默认为「Python脚本」。原有网址监控和腾讯云实例页仍保留为独立功能。关闭浏览器后，脚本继续在服务器运行。

普通 WorkBuddy 会话的分享网址、端口转发地址和会话 ID 不是腾讯云实例凭据。只有能在你有权限的 Agent Runtime 控制台中查询到对应 `InstanceId`，才能启用实例续期。实例续期可能增加腾讯云运行费用。

v1.7.1 增加 Python 单次运行时限与运行标识保护：限时由服务端执行，页面停止操作携带当前 `runId`，延迟到达的旧停止请求会返回冲突。日志或退出状态写入失败时仍会完成进程清理。共享账号、统一参数和已保存的沙盒配置继续保留。

v1.5.1 修复了从其他页面点击测试链接时误报 `invalid_origin` 的问题。仅放行首页的顶层导航，跨站管理接口请求仍被拒绝。

## 启动

安装 Node.js 24.15 或更高版本以及 Python 3（脚本仅使用标准库，无需 pip 依赖）。交付包已包含前端构建产物，解压后在项目目录执行 `npm start`。从源码获取或修改了前端时，先构建再启动：

```bash
npm ci --ignore-scripts
npm run build
npm start
```

打开 <http://127.0.0.1:8788>，添加你有权监控的部署网址。有独立的 `/healthz` 时可直接填该地址。保存后第一次检查通常在一秒内开始，繁忙时会等待空闲检查位。选择「立即检查」可测试暂停中的配置。

把监控服务部署在你能持续运行的设备上，例如 NAS 或 VPS。默认回环监听。需要从其他设备访问时，通过反向代理保留原始 `Host`，并配置 `WB_WEB_ORIGIN` 和 `WB_ADMIN_TOKEN`。HTTPS 不是必需的，内网 HTTP 直连也可以。登录状态默认保存在标签页会话中，刷新页面无需重新输入。

## 运行你的 Python 脚本

先设置 `WB_ADMIN_TOKEN` 并登录。进入「Python脚本 → 统一设置」，新增一个共享账号，填写 BASE、UID、JWT/RT；也可以从已有独立配置提取账号资料，原配置不会被修改。心跳、重连、TCP、脉冲、超时和日志等只在「脚本公共参数」统一设置一次。

返回「脚本配置」，新建沙盒时只需选择账号、填写名称与 CONV_ID，按需填写 SITE 和启用业务探测。其余设置默认继承统一参数。特殊沙盒展开「高级覆盖」，只有勾选的字段才独立保存；详情会标明来自共享账号、当前沙盒、统一默认还是单独覆盖。保存不自动运行，点击「启动脚本」才会启动真实 Python 进程。

旧配置仍完整保留原参数和凭据，显示为「旧独立配置」。停止后可选择共享账号切换；不切换则继续使用原值。统一设置变更只在下次启动生效，运行页可查看当前进程的启动快照。账号仍被配置使用时不能删除。运行时需先停止才能编辑沙盒参数。

服务端运行的是附件的脱敏副本 `server/python/workbuddy.py`，所有原函数保持一致，内置账号、令牌与业务地址已清空。平台将你保存的参数注入原脚本，不使用示例凭据。每份配置独立保存令牌状态文件和日志，最多 200 份配置，并行进程数不设上限（由每进程内存看门狗保护），可用 `WB_MAX_RUNS` 自行限流。日志页自动读取，最多显示最近 200 行，数据库保留每份配置最近 1000 行。前端日志隐藏令牌；原脚本直接写出的本地文件仍应作为敏感数据保管。

JWT/RT 在数据库中加密保存，加密密钥位于同数据目录的 `monitor.sqlite.python-key`，备份时务必连同该文件及 `python-tasks` 子目录一起备份。正常停止或平台重启不会自动重开任何脚本。脚本自身续期的令牌按配置版本隔离，未修改参数时下次启动可复用；页面显示的凭据是你手动保存的值。平台不保证云端保活成功，日志仍反映原脚本行为。

程序调用 `POST /api/python-tasks/:id/start` 时可选传入 `{"durationSeconds":900}`，由服务端在本次运行达到 900 秒时自动停止；未指定时不限时。任务响应中的 `runId` 标识本次进程，`runDurationSeconds` 表示本次时限。停止时传入 `{"runId":"本次返回的运行标识"}`，已过期的标识会返回 409，并保留当前进程。页面停止操作会携带该标识。为兼容既有调用，省略 `runId` 仍表示停止当前进程；需要防止延迟请求影响后续运行时必须传入标识。停止先发送 SIGTERM，5 秒内未退出再发送 SIGKILL。

## 修改管理口令

在「Python脚本 → 统一设置 → 管理口令」中，填写当前口令、新口令与确认值即可修改，无需重启服务，改动立即生效。

口令以 scrypt 加盐哈希保存在数据目录的 SQLite 中，不保存明文，接口也不会回显。新口令须为 8–128 位字母、数字、下划线或连字符，且不能与当前口令相同；少于 16 位时界面会提示强度较弱。修改成功后当前页面会退出登录，用新口令重新进入。

数据库中的口令优先于 `.env` 的 `WB_ADMIN_TOKEN`。忘记口令时，改回 `WB_ADMIN_TOKEN` 并重启即可恢复该初始值；登录后再从页面改回。若数据库中的口令记录损坏，服务会拒绝认证而不会回退到环境变量放行。

接口为 `POST /api/admin/password`，请求体 `{"current":"当前口令","next":"新口令"}`，需要先通过当前口令认证。备份数据目录时无需单独备份口令，它随 `monitor.sqlite` 一起保存。

## 并发与资源占用

并发数**没有硬上限**：既不限制同时运行的脚本份数，也不限制配置数量。资源安全由每个进程各自的内存看门狗保证，而不是拒绝启动。

实测单个 Python 进程（`workbuddy.py` 稳定运行，本机）：

| 指标 | 数值 |
|---|---|
| 线程数 | 2（主线程 + 1 个脉冲线程，`daemon=True`） |
| 常驻内存 RSS | 21–24 MiB |
| 虚拟地址空间 VmSize | ~175 MiB |
| 地址空间峰值 VmPeak | ~244 MiB |
| CPU 占用 | <0.01%，脉冲线程用 `time.sleep(1)` 空转 |

10 个进程并发实测合计约 210 MiB RSS；按 100 个进程估算也在 2 GB 量级。

内存看门狗（`server/python-memory.mjs`）每 10 秒采样一次进程 RSS，**连续 3 次**超过 `WB_MEMORY_CEILING_MB`（默认 512）才停止该进程，并把原因写进日志与推送。正常 21 MiB 远低于阈值，单次尖峰会被忽略。

早期尝试过 `RLIMIT_AS` 地址空间硬上限，已放弃：脚本的地址空间会因线程栈预留与 TLS 缓冲在 30–250 MiB 之间合法波动，硬上限会随机误杀正常进程（实测 8 次回归中有 3 次触发 MemoryError）。RSS 才是真正影响宿主机的指标。

如需人为限流，设 `WB_MAX_RUNS` 为正整数即可（默认 0 = 不限制）。

## 日志上限与清理

运行日志有两层上限，均无需人工干预：

- 数据库按任务裁剪：每份配置最多保留 `WB_LOG_LINES` 行（默认 1000，可设 100–5000），超出即删除最旧的行。
- 磁盘文件按体积轮转：Python 侧写入的 `keepalive-*.log` 超过 `WB_LOG_FILE_MB`（默认 4 MiB，可设 1–64）时，下次启动前改名归档。

「运行日志」区块有「删除日志」按钮，二次确认后同时清空该任务的数据库日志与磁盘 `keepalive-*.log`。`state-*.json` 与其它文件不会被删除。接口为 `DELETE /api/python-tasks/:id/logs`（单个任务）与 `DELETE /api/python-logs`（全部任务），都需要管理口令。

每条日志入库前会脱敏与截断：令牌、Bearer 头、48 位以上长标识替换为占位符，单行最长 4000 字符，控制字符被剥离。

## 状态推送（PushPlus）

在「Python脚本 → 统一设置 → 状态推送」中填写 PushPlus Token，即可在脚本启动、停止或异常退出时推送到微信。Token 使用与脚本凭据相同的加密密钥保存，页面只显示「已保存」，不回显明文；清空 Token 需显式勾选。

保存前必须提供 Token，否则启用会被拒绝。可选择「脚本启动」「脚本停止」「异常退出」三类事件，未勾选任何事件时不会发送通知。群组编码留空时推送给 Token 所有者。

推送只发送配置名称、PID、退出码和固定的中文状态描述，不包含令牌、会话 ID 或日志正文。推送失败（网络异常、上游错误码）不会影响脚本运行，也不会重试。保存后会调用 PushPlus 的 `/send` 接口；消息送达以 PushPlus 返回 `code=200` 为准。

调用 `GET /api/pushplus` 读取配置，`PUT /api/pushplus` 保存（`token` 为三态：省略保留、空字符串清除、字符串替换），`POST /api/pushplus/test` 发送测试消息。三个接口都需要管理口令。

## 运行总览

从 v1.3.0 起，打开管理台会先看到「运行总览」。这里按优先级汇总启用任务的连续失败、待检查、临近到期和续期核验状态。任务超过计划时间 60 秒仍未开始时，会单独提示检查调度，而不会判定为停机。点击事项直接打开对应网址或实例详情。已暂停的任务不会进入待处理列表。

总览比较时间时使用服务端时钟，并展示本次数据更新时间。它不会发起额外的云端操作；到期时间来自上次查询，不能用来断言实例当前已停止。

## 批量暂停

从 v1.5.0 起，可以在「运行总览」点击「批量暂停」。弹窗列出打开时已启用的网址检查和实例续期，默认不勾选。选择任务或点击「选择全部」，核对名称后点击「确认暂停」。后台只按显式选择的任务处理，不会影响未选的任务。

结果逐项显示「已暂停」「原已暂停」或「未确认暂停」。任务在操作期间被删除或解除绑定时，只影响该项，其余任务仍会处理。如果请求超时或断线，部分任务可能已经暂停；平台不自动重试，请先关闭弹窗并刷新核对状态。

暂停实例任务不会向云端发停止、删除或缩短期限请求，已发出的续期无法撤销。网址当前的检查可能会被取消；配置和历史都保留。要恢复任务，请到对应详情逐项启用。

## 单项配置

| 字段 | 默认 | 范围或说明 |
| --- | --- | --- |
| 名称、分组、备注 | 空 | 名称必填。分组用于筛选 |
| 部署网址 | 空 | HTTP 或 HTTPS 地址，可含端口及路径。请去掉用户凭据、查询参数和片段 |

| 超时 | 8 秒 | 2–30 秒，包含 DNS、连接、响应头及选填的正文检查 |

恢复成功时会清零连续失败次数。修改网址、请求方式、超时、成功码或预期文本后，列表和历史将显示新规则下的结果。检查记录只保存状态、耗时和判定结果。复制和导入的网址配置默认暂停，可逐项启用。导出 JSON 只包含网址检查配置，不包含实例绑定和续期策略。要备份续期策略或检查历史，先停止平台，再备份整个数据目录。

## 接入实例保活

1. 在腾讯云 Agent Runtime 控制台确认实例所属地域和 `InstanceId`。用专用子账号按最小范围授权 `DescribeSandboxInstances` 和 `UpdateSandboxInstance`，尽量限制至要管理的资源。参见[查询实例 API](https://cloud.tencent.com.cn/document/api/1814/139848)和[更新实例 API](https://cloud.tencent.com/document/product/1814/124814)。
2. 在部署机器维护权限为 `0600` 的 `.env`。设置 `WB_ADMIN_TOKEN`（用下文命令生成），再加入实例绑定。以下是配置结构示例，用你的实例 ID 和子账号凭据替换示例值：

   ```dotenv
   WB_AGS_BINDINGS='[{"id":"app-prod","label":"生产应用","region":"ap-guangzhou","instanceId":"ins-example-prod","credential":"TEAM_A"},{"id":"app-test","label":"测试应用","region":"ap-shanghai","instanceId":"ins-example-test","credential":"TEAM_B"}]'
   TEAM_A_SECRET_ID=REPLACE_WITH_CAM_SECRET_ID
   TEAM_A_SECRET_KEY=REPLACE_WITH_CAM_SECRET_KEY
   TEAM_B_SECRET_ID=REPLACE_WITH_CAM_SECRET_ID
   TEAM_B_SECRET_KEY=REPLACE_WITH_CAM_SECRET_KEY
   ```

   `credential` 可省略，默认前缀 `TENCENTCLOUD`；使用临时凭据时同时填入前缀对应的 `_TOKEN`。密钥不写入数据库、配置导出或浏览器。每个 `id` 和同地域的每个实例只绑定一次，最多 24 个。
3. 重启平台并登录，打开「实例保活」，选择实例。先点「查询实例」核对状态和到期时间；查询按钮只读，不会续期。按实例编辑策略，确认费用后勾选「启用自动续期」并保存。新绑定默认暂停；更换实例、地域或凭据身份后不会沿用旧绑定的启用状态。

| 实例策略 | 默认 | 可配置范围 |
| --- | --- | --- |
| 查询间隔 | 120 秒 | 60–1800 秒，不超过提前量的一半 |
| 提前续期 | 10 分钟 | 3–240 分钟 |
| 续期后时长 | 60 分钟 | 15–1440 分钟，至少比提前量多 10 分钟 |
| 自动续期持续时间 | 0（不限时） | 15–10080 分钟，到点后自动暂停此策略 |

从 v1.4.0 起可设置自动续期持续时间。启用时按服务端时钟计算一次截止时间并保存，重启不会重新计时。修改其他查询或续期参数不会延后截止；修改持续时间、或暂停后再次启用，才会从保存时重新计时。旧版策略默认为不限时，升级不改变启停状态。

到点后，后台会暂停该策略并记录「已到定时截止，自动暂停」。停机期间错过截止的，启动时先暂停，再考虑云端操作。这个设置限制的是**发送新续期请求的时间段**：不会停止、删除或缩短云实例的期限，已提交的续期也不会撤销。如果云端请求在截止前已经发出，结果仍会记录，可再用「查询实例」核验。

后端只延长仍处于 `RUNNING` 且到期时间落入窗口的非长期常驻实例；不会启动、恢复或新建任何实例。提交后单独记录云端受理状态，直到后续查询显示到期时间变晚才记录核验。两次续期尝试至少间隔 5 分钟。已停止、暂停、无到期时间及长期常驻的实例不发续期请求。暂停策略会阻止新的操作，已经发出的请求不能撤销。

从 v1.2.1 开始，同一个数据目录只允许一个平台进程启动。第二个进程即使用不同的 HTTP 端口也会退出。正常停止或进程崩溃后，操作系统会释放锁；同目录的 `.runner.sqlite` 锁文件可以保留，无需手动删除。请将 SQLite 放在支持文件锁的本地磁盘或本地 Docker 数据卷，不要用它做跨主机调度。后台运行需要把平台部署在持续在线的 NAS 或服务器上。

## 升级并保留数据

升级时**先停止旧服务**（v1.2.1 之前的版本不识别调度锁）。备份整个原数据目录，再解压新版；继续使用原 `WB_DATA_DIR`，或在 Compose 中沿用原项目名和命名卷。启动后确认原网址配置、检查历史及已有续期策略都在，不需要重新导入。

## Docker Compose

在没有现有 `.env` 的项目副本中生成管理口令并启动：

```bash
umask 077
node -e "process.stdout.write('WB_ADMIN_TOKEN='+require('node:crypto').randomBytes(32).toString('hex')+'\n')" > .env
docker compose up -d --build
```

打开 <http://127.0.0.1:8788>，输入 `.env` 中的 `WB_ADMIN_TOKEN`。容器重建后，数据保存在 `monitor-data` 命名卷。访问地址改变时同步调整 `WB_WEB_ORIGIN`。要在容器启用「实例保活」，把实例绑定和对应的凭据加在同一个本地 `.env`，再用 `docker compose up -d` 重建服务。

## 服务端设置

`npm start` 会加载项目目录中的 `.env`。现有进程环境优先。

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `WB_HOST` | `127.0.0.1` | 监听地址。非回环监听须同时配置口令与管理台来源 |
| `WB_PORT` | `8788` | Node.js 监听端口。Compose 固定使用容器端口 8788 |
| `WB_WEB_ORIGIN` | 回环来源 | 管理台对外来源，含协议、主机及端口。HTTP 与 HTTPS 均可 |
| `WB_ADMIN_TOKEN` | 空 | 8–128 位字母、数字、下划线和连字符。回环直连可选，外部访问必填 |
| `WB_DATA_DIR` | `data` | SQLite 所在目录。容器内为 `/app/data` |
| `WB_ALLOW_HTTP_TARGETS` | 已废弃 | HTTP 监控地址现在默认允许，此项保留只为兼容旧配置 |
| `WB_ALLOWED_ORIGINS` | 空 | 可选的部署来源限制。填写逗号分隔的完整来源，如 `https://example.com,https://example.org:8443` |
| `WB_CONCURRENCY` | `4` | 网址检查的并行数，允许 1–8（与 Python 脚本并发无关） |
| `WB_DENIED_DOMAINS` | 空 | 额外禁止监控的域名，逗号分隔，匹配自身与所有子域；内置项始终生效 |
| `WB_HISTORY_LIMIT` | `360` | 每项网址配置保留的检查数，允许 30–3000 |
| `WB_LOG_LINES` | 1000 | 每任务保留的日志行数上限，范围 100–5000 |
| `WB_MEMORY_CEILING_MB` | 512 | 单进程 RSS 上限（MiB），连续 3 次超限才停止，范围 128–8192 |
| `WB_MAX_RUNS` | 0 | 同时运行上限，0 表示不限制，范围 0–512 |
| `WB_LOG_FILE_MB` | 4 | 磁盘日志文件体积上限（MiB），范围 1–64 |
| `WB_AGS_BINDINGS` | 空 | 实例绑定的 JSON 数组。未配置时，仅提供网址监控 |

管理口令由本工具生成，和 WorkBuddy 登录凭据无关。检查目标需解析为公网地址，连接固定使用已校验的地址，并对 HTTPS 目标验证证书；HTTP 目标同样可以监控。

## WorkBuddy 发布和运行

- 对于 WorkBuddy 生成的网站应用，在预览工具栏选择「分享 → 发布」获取正式链接。可以在「设置 → 数据管理 → 应用」核对当前线上链接和发布状态。[WorkBuddy 网站应用发布文档](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Web-App)
- 应用用了云数据库、认证或存储时，查看对应应用的云服务用量。资源点耗尽会触发云服务暂停，恢复时间取决于套餐和额度。[WorkBuddy 云服务额度](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Cloud-Services)
- [WorkBuddy 开放平台云端任务](https://open.workbuddy.cn/docs/openapi)提供授权后的任务创建与查询。查询返回的 `expire_at` 是 ACP 网关凭据的过期时间。公开接口未列出已有会话沙盒的续期操作。
- WorkBuddy 企业智能体的 Runtime 页面可查看沙箱运行、休眠与失败状态。该产品的文档说明，会话空闲后可在再次访问时由平台自动唤醒。[企业智能体 Runtime 与 Session](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/CloudAgent#runtime-1)

## 验证与开发

```bash
npm test
npm run build
```

`npm test` 覆盖网址监控回归、官方 SDK 签名对照向量、实例绑定边界、独立调度、定时截止、重启恢复、旧客户端兼容、延期核验及批量暂停的部分失败处理。实例续期测试替换了云端响应，不会请求腾讯云或产生费用。

本地开发时，先在一个终端运行 `WB_WEB_ORIGIN=http://127.0.0.1:5173 npm start`，在另一个终端运行 `npm run dev`。打开 <http://127.0.0.1:5173>，Vite 会将 `/api` 转发至本机的 8788 端口。
